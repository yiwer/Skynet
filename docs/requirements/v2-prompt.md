### 四、V2 范围

**A. 会话组装与去重：可审计、可视化**

组装与去重的正确性在 V1 已有要求（AC-07、AC-08）。V2 要把每一次组装决策记录下来并展示出来：

- 每个会话记录组装结果：来源文件与快照代次、分块数、各类去重的条数与原因、谱系决策、组装状态、完成时间。
  - 去重原因分为：网络重试或重复投递、续聊复制的历史、压缩摘要派生内容。
  - 谱系决策包括：续聊合并、子会话侧链、离线补传并入、无法确定而保持分离。
  - 组装状态包括：已组装、组装中、存在缺口、待确认谱系。
- **新增“数据处理”页**：展示拾取 → 接收分块 → 去重 → 组装 → 解析与指标 → 报告的当日链路计数、原文可见延迟 P95、组装记录表、去重规则说明、待确认谱系列表、数据质量（各 Agent 的 Token 上报覆盖率），以及指标口径表。
- **会话详情侧栏新增“组装与去重”面板。**

**B. 对话视图**

- 会话详情默认以对话框形式展示用户消息与 Agent 消息，顺序与原件一致。
- 工具调用默认隐藏，提供开关展开；隐藏时在下一条 Agent 消息上注明“N 次工具调用（已隐藏）”。
- 两条消息之间显示等待回复时长，≥ 10 分钟高亮，并标注“期间在其他会话中活动”。
- 标出这些特殊内容：接入前旧内容（续聊同步）、离线补传、上下文压缩、采集缺口、进行中。
- 保留 V1 的时间线与原件 JSONL 视图：报告中的证据锚点跳到时间线原位置，对话锚点跳到对应消息。
- 消息原文只展示、不改写；Agent 自述但无工具结果佐证的，标“无工具结果佐证”。

**C. 活动记录（新页面）**

- 按北京时间逐条记录对话事件：会话开始与结束、提问、Agent 回复与追问、≥ 10 分钟的等待、≥ 3 分钟的权限等待、上下文压缩、采集缺口、离线与补传。
- 每条显示时间点、员工、会话、Agent、项目和原句摘录；截断的摘录标注省略号。
- 可按日期、员工、Agent、项目、事件类型筛选；点击跳到对话中的原句。
- 页面上方显示当天的“对话节奏”泳道图：每名员工一行，会话条按 Agent 着色，提问为点，返工提问为空心点，长等待为浅灰段，另有“现在”线。
- 迟到数据按来源时间归期，并标“补传”。

**D. 数据报表（Reporting 模块扩展）**

所有报表页共用一行筛选（时间范围、员工、Agent、项目），作用于整页；每张图都要有等价的“表格”视图。

- **D1 用量与产出**：
  - KPI：Token 输入与输出（已知部分，外加未上报会话数）、会话、提示词、工具调用、已验证结果（附“仅声称”数）、代码变更、测试通过率、会话内提交。
  - 每人 Token 按 Agent 堆叠；未上报的单独标“未知”，不画成 0。
  - 每人产出表，每列独立比例尺。
  - 会话散点：Token 与已验证结果。筛选员工时高亮该员工，其余作灰色参照；Token 未知的会话放在单独的“未知”列。
  - 每人每日 Token 小图。
- **D2 会话产效**：
  - 顶部的口径卡说明产效比、代码产出、等待占比。
  - 按任务类型分行的分布图，每行标中位数。
  - “值得复盘的会话”列表，入选条件为：Token 高于 P75 且没有已验证结果、声称多于已验证、返工 ≥ 2。
  - 可排序的会话明细。选中会话后显示“Agent 工作 / 等待回复 / 等待权限 / 缺口”分段条。
- **D3 提示词分析**：
  - KPI：提示词数、中位长度、提供上下文比例、返工率、无返工会话比例、Agent 追问率。
  - 员工 × 要素热力表，要素为目标、约束、上下文、验收标准。
  - “上一条是否提供上下文”与下一轮返工率的对比，并注明相关不等于因果。
  - 长度分段的数量与返工率，用两张图展示，不共用坐标轴。
  - 任务类型构成。
  - 写法示例：正、反各若干条，链接原句。
  - 每人一条写法建议，标注“模型推断”，定位为辅导参考。
- **D4 响应与等待**：
  - 口径卡，写明“等待不等于怠工，不用于考勤”。
  - KPI：等待回复中位数与 P90、10 分钟以上占比、权限等待中位数、期间在别处工作的占比。
  - 星期 × 小时的等待中位数热力图。
  - 每人等待分布，每行标中位数。
  - “让 Agent 停得最久的权限请求”列表，附允许列表建议。
- **D5 团队概览增强**：沿用 V1 的覆盖矩阵，在上方加本周 KPI 行（带每日趋势小图），在下方加“本周人员汇总”，包括会话、Token（已知 + 未知数）、已验证结果、代码变更、提示词 · 返工率、等待中位数、覆盖状态。人员固定按姓名排列。
- **D6 员工周视图“使用画像”**：该员工本周的 Token、已验证结果、提示词与返工率、等待中位数，以及每日 Token 小图；附“在报表中查看”链接，链接会带上该员工筛选。

**E. MCP**

新增查询能力：报表摘要（与 Web 同一范围、同一数值）、活动记录分页查询、会话对话分页读取（可选包含工具调用）、指标口径查询。Web 与 MCP 必须调用同一个指标服务。

### 五、指标口径（唯一定义，Web、MCP、导出共用）

| 指标 | 定义 | 来源与级别 |
| --- | --- | --- |
| 会话 | 有事件的会话，含子会话，按来源时间归期；续聊合并为同一会话 | 原件 · 确定性 |
| 提示词（用户轮次） | 用户提交的消息，不含工具结果与压缩摘要 | 原件 · 确定性 |
| 工具调用 | Agent 发起的工具调用次数 | 原件 · 确定性 |
| Token 输入 / 输出 | 客户端记录的用量；未上报标“未知”，不计为 0，不进入比值 | 原件 · 确定性 |
| 代码变更行 | 会话内 Edit / Write / apply_patch 等工具的增删行 | 原件 · 确定性 |
| 测试运行 / 通过 | 从工具输出中解析出的测试运行与通过次数；不采信 Agent 陈述 | 原件 · 解析 |
| 会话内提交 | 会话中执行的 git commit | 原件 · 确定性 |
| 已验证结果 | 报告中有工具结果佐证的结果条目 | 模型提取 + 证据核对 |
| 仅声称 | 只有用户或 Agent 陈述、没有工具结果的结果条目 | 模型提取 |
| 产效比 | 已验证结果 ÷ 百万 Token（已知）；只在同类任务间参考 | 派生 |
| 代码产出 | 代码变更行 ÷ 百万 Token（已知） | 派生 |
| 任务类型 | 实现 / 修复 / 排查 / 重构 / 测试 / 运维 / 整理；可在日报中更正 | 模型推断 |
| 提示词要素 | 目标、约束、上下文、验收标准是否出现 | 模型推断 |
| 返工率 | 纠正或推翻上一轮结果的提示词 ÷ 非首条提示词 | 模型推断 + 规则 |
| Agent 追问率 | Agent 向用户澄清需求的次数 ÷ 提示词 | 模型推断 |
| 等待回复 | Agent 本轮结束（等待输入）到用户下一条消息的间隔；会话最后一次回复之后的空闲不计 | 原件时间戳 · 确定性 |
| 权限等待 | Agent 发起命令确认到用户批准或拒绝的间隔 | 原件时间戳 · 确定性 |
| 期间在别处工作 | 等待期间，同一员工在其他会话中有事件 | 原件时间戳 · 确定性 |

各客户端能否识别“本轮结束”和“权限请求”，取决于 Adapter 实际能拿到的事件。逐个客户端核实后写入口径文档；拿不到的显示“未知”，不要用启发式猜测后当作确定值。

### 六、不可违反的守则

1. 使用能力评估是唯一允许的综合指数，按 PRD v2.0 的固定锚点、任务类型校正、样本和可信度规则执行。不合成整体绩效分，不提供排名、Top / Bottom 榜单或按指标排序的人员列表及导出；人员表与评估分组内固定按姓名排列。会话明细表可以排序。
2. 比值必须同时展示分子与分母，并注明“只在同类任务之间参考”；Token 未知的会话不参与比值。
3. 未知不等于 0：未上报的字段显示“未知”，不画成 0，不进入趋势线；合计写成“已知部分 + N 个会话未知”。
4. 证据分级：推断字段标注“模型推断”，可以更正、重算，并保留版本；“已验证”只计有工具结果佐证的条目。
5. 等待不等于怠工：不折算工时，不做考勤，不设超时惩罚类提醒；长等待旁同时显示“期间在其他会话中活动”；权限等待单列，定位为流程问题。
6. 同源可重算：所有报表、MCP 与导出来自同一指标服务；指标可以从原件重算；页面标注数据截至时间，并链接口径。
7. 沿用 V1：分析 Worker 不执行原文中的指令；系统分析会话不计入员工活动；认证后共享查看；原件不可覆写。
8. 不伪造数据：测试只用合成会话；界面不出现无来源的数字。

### 七、架构与实现要求

- 沿用 V1 技术栈与模块边界：TypeScript/Node、Fastify、PostgreSQL、原件持久卷、React/Vite；分析由独立的 Claude Code Worker 调用千问按量 Anthropic 兼容接口。
- 确定性指标放在 Evidence 与 Reporting 之间，由规范化事件计算，按会话和快照代次物化，支持增量更新与全量重算。
- 推断字段（任务类型、提示词要素、返工、追问、已验证 / 声称）扩展进分析输出 schema：
  - 每个字段都带证据位置与分析版本。
  - 旧任务的结果不能覆盖较新版本。
- 组装与去重决策写入审计记录，不修改原件。
- 前端的颜色与字体沿用原型的设计令牌，包括校验过的图表色：浅色为 #3d8ce6、#e36d24、#16a08f、#7a5bd3，深色为 #3f8fe6、#dd7230、#1ca894、#8a74e2。
- 图表规范：
  - 细标记，2px 间隙，发丝网格。
  - 提示层“值在前、标签在后”，键盘可达。
  - 散点图最多 3 种颜色，其余用强调 / 灰色参照。
  - 不用双 y 轴。
  - 每张图有表格视图。
- 界面在 320—1920 px 下无横向滚动，浅色与深色主题的对比度都达标。

### 九、V2 验收标准

| 编号 | 场景与通过标准 |
| --- | --- |
| AC-23 | 指标同源：同一筛选范围下，Web、MCP、导出数值一致；日、周、人的汇总等于会话级指标之和（已知部分）；从原件全量重算后结果一致 |
| AC-24 | 未知处理：未上报 Token 的会话显示“未知”，不计 0，不进入比值与趋势；“数据处理”页显示各 Agent 的上报覆盖率 |
| AC-25 | 组装与去重：注入重复分块、ACK 丢失重试、续聊复制、压缩摘要、子会话、离线补传后，轮次、Token、工具调用、等待都不重复；每个会话可见来源、去重条数与组装结果；无法确定谱系时保持分离并提示 |
| AC-26 | 对话视图：消息顺序与原件一致；工具调用默认隐藏，可以展开，数量正确；等待时长与原件时间戳一致；证据锚点与对话锚点跳转正确；旧内容、补传、压缩、缺口有标识 |
| AC-27 | 活动记录：每条事件的北京时间、员工、会话、原句摘录正确；筛选与跳转可用；迟到数据按来源时间归期并标“补传” |
| AC-28 | 已由 PRD v2.0 修订：允许使用能力评估指数；不提供名次、榜单、按指数或指标排序的人员列表或导出；人员表和等级组内按姓名排列；比值、推断、更正、版本与数据截至时间按当前 PRD 核查 |
| AC-29 | 等待口径：只计 Agent 本轮结束到用户下一条消息；会话结束后的空闲不计；权限等待单列；“期间在别处工作”标记正确；客户端不提供事件时显示“未知” |
| AC-30 | 提示词分析：要素、类型、返工、追问由分析任务产出并附证据位置；分析失败或未完成时显示“未完成”，不显示 0 |
| AC-31 | 可访问性：每张图有表格视图；提示层在键盘聚焦时同样可用；320—1920 px 无横向滚动；浅色与深色对比度达标 |
| AC-32 | 性能：报表与活动记录在试点数据量下的响应目标**由用户确认后填写**，交付时报告实测 P50 / P95 |
| AC-33 | 回归：V1 的 AC-01…AC-22 与 G0—G4 仍全部通过 |

AC-34…AC-38 分别覆盖评估计算、样本与可信度、可追溯版本、更正与复核、员工一览与画像；完整判定与发布门槛以 [PRD v2.0](./PRD-v2.md) 为准。

- 主要页面在浅色、深色和 375 px 宽度下的截图或录屏。

### 十一、工作方式

- 本轮在 `codex/v2` 分支按切片实施；提交、推送与 PR 动作按当前用户授权执行。
- 每个切片完成后说明：做了什么、怎么验证的、还有什么未解决。测试失败时如实附上输出。
- 只用合成数据，不读取真实员工材料；界面和报告中不出现无来源的数字。
- 发现冲突时先按 PRD v2.0 的覆盖关系和当前用户指示处理；未被覆盖的新产品取舍列出具体差异供用户决定。
