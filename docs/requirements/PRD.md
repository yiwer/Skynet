# Skynet PRD v1.0：Coding Agent 工作观察与会话存档

日期：2026-09-24。产品形态：内部自用的 Web + MCP server + 员工端采集器。

依据：用户已确认需求、历史采集边界与整体架构。本 PRD 是当前首版产品及验收依据；技术兼容性、性能和原生恢复仍须实测，设计确认不代表实现通过。

文档状态：已完成需求合成，可供实现与评审。已发布为 [GitHub Issue #1](https://github.com/yiwer/Skynet/issues/1)，标签为 `ready-for-agent`；实现与技术验证待执行。

## Problem Statement

管理者希望了解员工每天、每周使用 Coding Agent 的真实工作方向、推进过程、会话内成果和阻塞，并据此核查工作、形成绩效参考。目前材料分散在员工设备和不同 Agent 的会话中，仅靠口头汇报或手工日报难以追溯，额外填报还会占用员工时间。

员工已经完全同意本项目的数据采集。产品需要把安装、绑定和日常使用负担降到最低：接入后照常使用 Claude Code CLI、Codex CLI、Codex Desktop，不需要特殊提示词、主动调用上报工具或每天操作平台。

员工还需要在本地会话丢失时从服务器找回完整记录，并在原 Coding Agent 中继续对话。只有摘要、活动统计或可读文本下载，不能独立满足这项需求。

平台所能证明的是实际收到的会话材料及其中可追溯的活动。它不能把 Agent 自述直接等同于已验证成果，也不能用 token、消息数量或并发会话时长证明精确人工工时或员工价值。

## Solution

构建统一的本地采集器，通过各 Agent 的 hooks 和原生会话 Adapter 自动发现活动、保存原件并上传。npm 和 Agent 插件市场是可选的安装入口，共用设备身份、后台和持久队列。员工只提供一个个人授权值，完成一次初始化及宿主必要信任后正常工作。

平台保存完整可获得的会话原件，提供按员工、项目、工作主题组织的日工作视图和周工作视图。每个关键结论能够回到原文证据；人工补充、更正与重新汇总保留历史版本。所有已认证用户可查看全部数据，首版不做按员工或团队划分的读取隔离。

平台使用独立运行的 Claude Code 执行分析任务，通过千问AI平台按量 Anthropic 兼容接口调用模型。原件接收与分析解耦：模型故障、超时或预算耗尽时，会话存档、查看和导出仍可继续。

### 首版产品流程

1. **接入：** 取得个人授权值，按安装页选择适用入口，完成一次初始化、身份绑定及必要信任，查看各客户端真实接入状态。
2. **正常工作：** 三种目标客户端在所有项目中的新会话自动同步；接入后继续使用的旧会话从现存记录开头完整同步；其余旧会话不批量导入。
3. **查阅：** 管理者和员工在 Web 或 MCP 中查看会话、项目、日/周工作、工作主题、阻塞与证据，同时了解采集覆盖和分析状态。
4. **更正：** 已认证用户追加说明、更正分析归类并重新生成；记录修改人、时间和版本，原始会话不被覆盖。
5. **找回：** 从服务器导出完整可读材料或原生恢复包，在隔离目标位置完成校验，再回原 Agent 继续对话。

### 范围和发布标准

| 项目 | 首版要求 |
| --- | --- |
| 客户端 | Claude Code CLI、Codex CLI、Codex Desktop；具体支持的 OS、版本与运行环境须有验证记录 |
| 安装 | npm 单授权变量加一次初始化为优先路径；各 Agent 插件市场为已接受的替代或补充入口；员工无需双重安装 |
| 数据 | 所有项目、符合采集资格的全部会话及原生可获得的对话、工具记录、代码变更与关联材料 |
| 历史 | 不批量导入未继续的旧会话；继续旧会话时同步该会话完整可得记录；离线补传照常执行 |
| 工作观察 | 日/周工作、项目、跨会话工作主题、结果、阻塞、活动统计、证据与分析更正 |
| 会话找回 | 完整可读导出和原生续聊均为必需；Codex 恢复未通过不能视为完整首版完成 |
| 运行 | 无需日常手动上传；错误和数据缺口可见；采集失败不阻止正常编码 |
| 产品成功 | 员工不增加日常填报；管理者可从总结追溯证据；服务器存档可独立用于找回 |

“全部会话”受上述时间资格约束，不要求安装时把所有旧会话扫入服务器。“完整”按来源实际保存且可获得的材料判断；上游未保存、已清理或无法访问的内容必须显示缺口。

## User Stories

以下按统一格式“作为某类使用者，我希望某项能力，以便获得某种价值”编号；编号用于验收追踪，不表示必须拆成独立开发任务。

### 安装与使用

1. 作为员工，我希望平台提供适合当前环境的安装入口，以便无需自行判断复杂的 Agent 集成方案。
2. 作为员工，我希望通过 npm 安装后只提供一个个人授权变量并初始化一次，以便快速完成接入。
3. 作为员工，我希望可以采用平台支持的 Agent 插件市场入口，以便在熟悉的 Agent 中完成安装。
4. 作为员工，我希望初始化自动检测已安装的目标客户端并绑定我的身份，以便不用重复填写员工和设备信息。
5. 作为员工，我希望无需手工编辑多份配置或逐项目安装，以便所有项目自动覆盖。
6. 作为员工，我希望接入时保留已有插件和 hooks 配置，以便原有工作方式继续可用。
7. 作为员工，我希望安装器明确引导宿主要求的信任操作，以便知道还需完成什么步骤。
8. 作为员工，我希望区分已安装、待信任、后台运行、首次采集和已上传状态，以便确认接入真正有效。
9. 作为员工，我希望个人授权值通过本地受控输入完成绑定，以便不必把 Key 发进模型对话。
10. 作为 Codex Desktop 使用者，我希望从图标启动应用也能采集，以便无需每次从设置了环境变量的终端启动。
11. 作为使用多台设备的员工，我希望设备各自接入同一个员工身份，以便工作能够正确汇总。
12. 作为员工，我希望接入后后台自动运行并在受支持的登录环境恢复，以便不必每天启动采集程序。
13. 作为员工，我希望重复初始化或修复不会增加重复后台和 hooks，以便放心处理接入故障。
14. 作为员工，我希望升级保留身份、未上传数据和已有配置，以便不中断工作记录。
15. 作为员工，我希望能够明确卸载整体采集器或移除单个插件入口，以便控制本机安装且不误伤其他仍在使用的入口。

### 采集与同步

16. 作为员工，我希望 Claude Code CLI、Codex CLI、Codex Desktop 都有经过验证的采集入口，以便无需改变惯用工具。
17. 作为员工，我希望接入后的新会话自动同步，以便无需主动上报或填写日报。
18. 作为管理者，我希望所有项目均被采集并可按项目区分，以便完整了解工作方向。
19. 作为员工，我希望安装时不批量上传尚未继续使用的旧会话，以便遵循约定的历史边界。
20. 作为员工，我希望继续旧会话后同步该会话完整可得记录，以便保留理解与恢复需要的上下文。
21. 作为管理者，我希望存档保留完整对话、命令、工具结果和会话内代码变更，以便核查实际过程。
22. 作为管理者，我希望子会话和分支与来源会话关联，以便理解并行活动而不重复计算。
23. 作为员工，我希望 compact、重写或截断后仍保留服务器已收到的早期原件，以便已存档上下文不会被后来的摘要替代。
24. 作为员工，我希望断网后材料本地暂存并在恢复连接时补传，以便网络波动不会要求手动整理记录。
25. 作为管理者，我希望重复投递、重启和重试不会增加重复活动统计，以便数据规模可信。
26. 作为员工，我希望采集和服务器故障不会阻止继续编码，以便平台不会成为工作阻塞点。
27. 作为已认证用户，我希望明确看到丢失、不可读取或未支持的材料，以便不把部分记录误认为完整存档。

### 会话找回

28. 作为员工，我希望本地记录丢失后仍能在服务器找到已存档会话，以便恢复工作上下文。
29. 作为已认证用户，我希望导出完整可读会话，以便离开平台也能核查材料。
30. 作为员工，我希望下载恢复包后能在原 CLI Agent 中继续原生会话，以便接着之前的工作进行。
31. 作为 Codex Desktop 使用者，我希望按明确流程在桌面端打开恢复会话并继续对话，以便会话找回覆盖实际使用入口。
32. 作为员工，我希望恢复前校验材料并默认使用隔离目标位置，以便不覆盖现有会话。
33. 作为管理者，我希望复制或恢复后的历史保留原员工归属，新活动归属当前使用者，以便人员工作记录不混淆。
34. 作为员工，我希望导出时看到来源版本、完整性和已验证恢复能力，以便知道恢复包能够支持什么。
35. 作为平台维护者，我希望服务器备份也能经过独立恢复演练，以便员工端同步成功后仍有可靠的服务端保障。

36. 作为管理者，我希望日工作视图呈现员工当天目标、行动、结果与阻塞，以便了解每天工作进展。

## Implementation Decisions

### 1. 已确认的架构与技术选择

- **统一采集核心：** 本地后台承担会话资格登记、原件快照、持久缓冲和同步；npm 与 Claude/Codex 插件入口不各自维护独立采集器。
- **Module 职责：** Enrollment & Runtime 负责绑定和生命周期；Agent Integration 负责宿主集成、原生材料和恢复；Local Capture & Delivery 负责采集与可靠传输；Archive 负责不可变原件；Evidence 负责事件解析与证据；Analysis 负责分析任务；Reporting 负责视图、汇总和分析更正。
- **Interface 原则：** 对外呈现少量业务操作与明确状态，内部隐藏配置格式、路径、重试和版本差异。Web 与 MCP 复用 Reporting / Evidence，不分别计算事实。
- **Adapter 范围：** Claude 与 Codex 是实际原生格式差异；Windows、macOS、Linux 的后台机制分别适配。远程环境以真正执行 Agent 的环境为采集位置。
- **服务端部署：** 采用模块化单体，分析 Worker 独立进程或容器。首版 Linux 单机、Docker Compose、TypeScript/Node、Fastify、PostgreSQL、原件持久卷，Web 使用 React/Vite。
- **客户端运行：** npm 路径以 Node LTS 为基础，先验证 Node 24；避免需要员工本地编译的依赖。插件预构建产物是否能够免 Node/npm，由实际打包和干净环境验证决定。

### 2. 安装、身份与生命周期

- 安装页提供 npm 和适用的插件市场路线；npm 先验证，市场入口共用同一初始化和采集契约。三个目标客户端均须有有效接入路径；不以公开官方目录上架或员工同时使用两种渠道作为首版前提。
- npm 路径采用安装包、设置唯一授权变量 SKYNET_KEY、执行一次 setup 的流程。初始化不能依赖安装期脚本必然执行；插件安装也不能被当作后台已运行的证明。
- 企业发行配置预置可信平台地址，员工不用填写第二个地址变量、员工 ID、项目列表或模型凭据。私有包、私有市场需要额外下载认证时，安装页须说明，不能藏进“只需一个 Key”的承诺。
- 个人注册值由平台换成独立设备凭据，绑定确定的员工身份。凭据在用户受限存储中保存；Desktop 和登录后台不依赖安装终端持续存在。设备上传、Web 登录及 MCP 查询使用各自适用的认证，不互相代替。
- 重复接入、修复和多入口安装保持幂等；同一用户执行环境共用后台、队列和设备身份。Windows 与 WSL 等独立环境分别登记，不能靠一份宿主配置假定全部覆盖。
- 宿主必要的信任、重启和工具执行许可走官方流程。安装器保留已有配置，仅修改自己拥有的条目，不伪造信任状态。
- 后台以当前用户运行，目标是在受支持设备上无需管理员权限接入。关机、注销或系统策略禁止后台时不承诺持续在线，恢复运行后补传。
- 程序更新与运行中后台升级分别管理，保留未确认队列并可回退。稳定运行位置不依赖会被清理的插件缓存。移除一个插件不误停其他入口仍使用的后台，完整卸载使用明确的产品入口。

### 3. 采集资格与完整性

- 新会话或接入后被继续使用的旧会话，由宿主活动信号登记。未继续的旧会话不进入批量扫描/上传；文件修改时间变化不能单独作为继续使用的证明。
- 被继续的旧会话首次从现存原件开头同步，并关联恢复必需的原生材料；之后保存增量。保留接入前内容的原始日期，今天的上传流量不代表今天的工作量。
- 采集对话、工具请求/结果、命令、会话内代码变更、可得用量以及原生关联子会话/附件。模型未暴露的内容或上游已丢失的材料标为不可得，不生成替代原件。
- 不把整个 Agent 配置目录或任意工作文件作为备份载荷；账号登录状态、模型凭据和采集凭据不属于会话存档。
- hooks 只承担短时本地记录，后台读取和上传原件；编码过程不等待远端网络或模型分析。后台核对已登记材料，减少单次 hook、文件监听或异常退出带来的遗漏。
- 文件增长采用增量快照，重写/截断采用新代次，旧代次保持不可变。原件存档与事件解析分离，部分行、未知格式或解析失败不被误计为完整业务事件。
- 完整性按来源、材料集合和覆盖范围记录：已收到部分、同步中、存在缺口、当前快照完整、原生恢复已验证是不同状态。

### 4. 上传、存储与数据契约

| 契约 | 必须保持的业务语义 |
| --- | --- |
| 设备登记 | 绑定员工、设备和实际运行环境；重复初始化返回一致身份，不接受任意自报员工归属 |
| 原件上传 | 携带来源、稳定标识、版本、长度和哈希；至少一次投递，同键同内容重试幂等，同键不同内容报冲突 |
| 快照提交 | 清单引用的分块全部持久化并校验后才提交；登记后续任务与清单状态保持一致 |
| 接收确认 | 仅确认已完成持久化提交的范围；不将收到请求或尚在内存中的载荷当作备份成功 |
| 证据读取 | 每个规范化事件与分析引用可定位至确定原件快照和位置；解析版本变化不改变原件 |
| 分析结果 | 记录输入范围、模型、运行时、提示版本、状态与证据；旧作业结果不能覆盖较新版本 |
| 报告与更正 | 追加版本、修改人和修改时间；保留原报告、来源与更正，不覆写原始证据 |
| 导出与恢复 | 返回完整性、来源版本、材料清单和校验信息；恢复检查目标兼容性且默认不覆盖已有状态 |

核心记录包含员工、设备、来源实例、会话及谱系、原件/分块/快照清单、规范化事件、工作主题及关联、分析任务、报告版本和分析更正。来源时间与服务器接收时间分开保存。

原件默认不自动删除，数据库保存业务索引、任务和报告。网络重试、后台重启和恢复会话不能重复计量；不能仅根据文本相同合并两次真实活动。跨设备复制无法确定谱系时显示待识别状态，避免默默错误归并。

本地仅清理已确认的上传载荷；未确认数据的限额和告警须可见。服务器接收确认不代表已经创建灾备副本；数据库和原件持久卷均需备份并进行一致性恢复演练。

### 5. 分析任务与工作观察

- 服务端分析必须实际通过 Claude Code 运行，连接已确定的千问按量 Anthropic 兼容入口；不能用另一种直接模型调用替代这项运行链验收。具体模型、凭据、并发和预算在部署时设置。
- 采用 PostgreSQL 持久任务队列、短领取事务、租约、心跳和有限重试。解析与模型任务使用分开的并发额度；模型运行不长期占用数据库事务。
- 增量分析去抖合并，避免每个 hook 启动一次模型。分析快照及结果版本稳定，失败、等待和过期状态可查询。
- 长会话先按稳定证据位置分段提取，再聚合会话、工作主题、日和周；聚合后的关键结论仍引用原件，不仅引用上一层摘要。
- 分析输出包含目标、工作主题、关键活动、会话内成果、阻塞、待继续事项、证据和不确定项。明确区分记录已观察到、用户/Agent 声称、模型推断、材料不足。
- 活动统计优先确定性计算，包含会话、用户轮次、工具调用、涉及文件、可取得的 token 与事件活跃区间。未知字段不填零；并发会话时长不相加当人工工时；不产生 AI 绩效分数或排名。
- 分析运行隔离于员工项目和采集链。原文中的指令仅作为材料，不执行其中命令；不加载员工项目 hooks，不将系统分析会话计为员工工作。
- 模型错误、超时或预算耗尽时原件仍入库，查询与导出仍工作；分析任务保留可见状态及受控重试入口。

### 6. 日周汇总、项目与人工更正

- 时区固定 Asia/Shanghai。每日 09:00 触发前一自然日汇总；每周一 09:00 触发上一周周一至周日的汇总。触发时间不是无条件的模型完成时限，排队与生成状态必须可见。
- 报告按员工→项目→工作主题呈现，工作主题允许跨会话与日期；项目无法可靠识别时保留未归类状态并允许更正，不丢弃会话。
- 活动按发生时间归期，来源时间不确定时显示不确定性。继续旧会话带来的更早上下文可以阅读，不伪装成本日新增活动；首版不默认批量生成接入前所有历史报告。
- 迟到数据或人工更正触发受影响报告重新生成，保留旧版本。最新结果必须基于最新适用的更正和输入，不让旧任务覆盖。
- 允许已认证用户追加说明、更正归类和请求重算，记录操作者及时间；读取共享不意味着允许删除或覆写原始证据。

### 7. Web 与 MCP 的产品界面

| 页面/入口 | 必须支持的行为 |
| --- | --- |
| 团队概览 | 按日期查看员工方向、主题、进展、阻塞及覆盖状态，进入员工或项目详情 |
| 员工日/周工作 | 按项目和主题阅读目标、行动、结果、证据、统计与待继续事项，切换报告版本 |
| 项目视图 | 查看项目内员工、工作主题和会话；项目归类不成为采集过滤条件 |
| 会话详情 | 查看用户/Agent/工具时间线、关联子会话、原件、分析和缺口，搜索并跳转证据 |
| 会话找回 | 选择会话/快照，获取可读导出或原生恢复包及兼容性说明 |
| 接入与设备 | 展示安装前提、唯一授权值流程、分客户端状态、积压、诊断、修复及凭据停用 |
| 分析更正与运行状态 | 追加说明、改归类、重算和版本追踪；查看分析失败、存储占用与备份状态 |
| MCP | 查询会话、读取分页原文、查询日/周报告、定位证据、准备导出，与 Web 复用相同业务结果 |

员工、日期、项目、Agent 和会话内容提供检索入口。大输出分页或按需展开，阅读优化不减少原件与导出内容。空状态区分无活动、待信任、设备离线、采集缺口和分析未完成。

MCP 采用 HTTPS Streamable HTTP，按目标客户端支持的授权规范连接个人账号。查询认证是使用查询能力时的首次授权，不给自动采集增加第二个环境变量或每日操作。MCP 不承担被动监听全部活动的职责，也不因自身登录失败阻断上传。

### 8. 会话找回

- 完整可读导出与原生恢复包分别提供。包中包含来源、版本、原件及必要关联材料、清单和哈希；不把摘要或新聊天中粘贴全文当原生恢复。
- 恢复先下载到隔离位置，验证完整性、目标版本和兼容性，再执行目标 Adapter 的已验证步骤；不覆盖正在使用的会话状态。
- Claude CLI、Codex CLI、Codex Desktop 都需独立验证相关原生续聊流程。原机器仍有会话时调用 resume，不构成“只从服务器备份恢复”的证明。
- 支持能力按 Agent、版本、OS、运行环境登记，缺口如实表达。Codex 原生恢复未通过时，首版核心需求仍未满足，应解决恢复路径或明确支持组合后再发布完整版本。
- 历史材料保留原员工归属，恢复后的新工作记入当前使用者并关联谱系。会话找回不包括恢复代码工作区、依赖、运行进程或 Agent 登录状态。

### 9. 非功能目标

| 项目 | 目标及测量口径 |
| --- | --- |
| 安装负担 | 员工只输入一个个人授权值，不手改多份配置；安装与本地健康检查目标两分钟内，Node/Agent 前置安装、下载、宿主信任及首次大历史同步分别记录 |
| 日常负担 | 正常使用无需手工启动上传、额外提示词或日报填报 |
| 原文可见 | 受支持客户端、网络正常、约定试点负载下，从事件发生至可查询原文的 P95 目标不超过 60 秒；首次旧会话大体积回填另计 |
| hook 影响 | 包含进程启动与本地写入的 P95 样机目标不超过 100ms；不等待远端；不满足时优化设计并记录实测，不伪称达标 |
| 可靠性 | 重试不重复计数，确认范围不虚报；磁盘满、读取失败或源头丢失必须显示缺口 |
| 可维护性 | 安装、升级、修复、整体卸载和服务器恢复有可重复流程，不依赖员工修改内部状态 |
| 用量 | 分析并发、作业时间、输入规模与预算有限额；未知用量不当零用量，超限状态可见 |

员工数量、设备数、实际 OS/版本、网络、磁盘、服务器备份策略和模型预算尚未提供。以上为验收目标，具体压测基线与能力范围在试点登记，不虚构统一容量、工期或全部平台已兼容。

## Testing Decisions

### 测试 Seam

沿用已确认架构和验证计划中的业务边界，不新增专为测试绕过产品流程的入口。**主要验收 Seam 是员工与已认证用户可操作的完整产品流程：安装/绑定 → 产生已知活动 → 观察同步状态 → 查询原件/报告 → 导出 → 原生恢复。** 测试通过公开 Interface 和可见状态断言结果，不直接断言内部表名、目录布局、线程数或某个辅助函数被调用。

必要的定向验证复用现有设计中的 Agent Integration Seam，覆盖 Claude/Codex 原生格式和不同 OS 的接入/恢复；复用 Analysis Seam，覆盖结构化结果、证据与失败语义。不为每个数据库实体再造一套 mock Interface。

测试对象覆盖 Enrollment & Runtime、Agent Integration、Local Capture & Delivery、Archive、Evidence、Analysis、Reporting 及其 Web/MCP 入口。优先在最高可行层验证一个业务性质，并仅在故障定位和版本格式确有必要时补充更低层契约测试。

### 好测试的标准与现有基础

- 使用合成会话和隔离环境，输入含已知员工、项目、时间、工具结果、父子关系与预期证据位置；不读取真实员工材料或删除真实会话来制造丢失。
- 判断用户可观察的行为：材料是否可读、是否完整、归属是否正确、报告是否有证据、故障是否显现、能否真实续聊；不以内部实现与测试代码相似作为正确性证明。
- 故障注入只改变外部条件或已定义契约，例如断网、重复上传、确认丢失、进程退出、过期租约、损坏材料和模型错误。
- 模型测试断言输出结构、有效来源、关键事实与不得越界的行为，不要求随机生成文本逐字一致。确定性替身适用于故障路径；真实 Claude Code + 千问调用仍须单独验收。
- 当前工作区只有研究、需求、架构和验证文档，没有产品实现、测试框架或可复用测试代码。现有先例是已确认的 G0—G4 验证计划及需求样例；实施时复用其场景，不声称已经存在通过的测试套件。

### 发布门槛

1. **G0：来源与恢复。** 优先证明三客户端的活动识别、原件取得、历史边界及原生续聊，尤其 Codex Desktop；失败不能以文本导出替代。
2. **G1：安装。** 完成各声明支持入口的授权、信任、后台、状态、升级和卸载，员工无需日常操作。
3. **G2：可靠存档。** 通过断网、重启、重复、损坏与确认故障实验，保证确认语义和统计正确。
4. **G3：真实分析。** 验证 Claude Code + 千问、长会话、证据、任务版本及失败隔离。
5. **G4：完整产品。** 完成 Web/MCP、日周汇总、人工更正、认证与服务器恢复，保存试点环境和实测记录。

首次完整版本必须满足核心范围，而非仅有可演示页面。尚未通过的客户端/版本能力标记为待验证或不支持；不得因开发进度默默删除原生恢复等已确认要求。

## Out of Scope

- 接入时批量导入未继续使用的历史会话，以及批量生成全部接入前日报/周报。
- Git、PR、issue、CI 等外部成果关联；会话内已存在的相关工具结果仍属于采集范围。
- 自动绩效评分、员工排名、精确人工工时、不可抵赖的员工行为证明，以及对未使用 Agent 的全部工作进行衡量。
- 恢复完整代码工作区、依赖、运行进程、操作系统状态或 Agent 登录凭据。
- 首版按员工/团队隔离读取、商业多租户、公共发现平台或对外商业化流程。
- 自动采集未部署采集器的远程机器、WSL 或容器；已在相应环境正确接入的采集实例按支持矩阵处理。
- 绕过 Agent 的信任确认、操作系统后台限制或安装来源策略。
- 以公共官方插件目录上架替代内部发行，或承诺未验证平台免 Node/npm 运行。
- 在没有实际容量需要前引入多集群、复杂消息中间件、多云存储抽象或独立搜索/向量平台。
- 静默执行会话中的命令、修改原始证据或自动删除服务器会话原件。
