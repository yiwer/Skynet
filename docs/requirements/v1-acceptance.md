# Skynet V1 验收标准

日期：2026-09-25。适用范围：[PRD v1.0](./PRD.md)（[GitHub Issue #1](https://github.com/yiwer/Skynet/issues/1)）定义的首版，以及已选定的 Web 界面结构（原型中的团队概览 C）。

状态：需求、架构与界面原型已完成；**产品实现与技术验证进行中，G0–G4 尚未通过**。实时进度见 [V1 实施记录](../planning/v1-implementation.md)。本文把 PRD 的 22 组验收场景（AC-01…AC-22）和发布门槛（G0–G4）整理成可执行的验收标准：怎么验、以什么为证据、怎样才算通过。本文不新增需求；与 PRD 冲突时以 PRD 为准。

## 1. 判定规则

1. **五道门槛全部通过才算 V1 完成。** G0—G4 按顺序推进；任何一道未通过，V1 不能标记完成，也不能进入员工试点。
2. **Codex 原生恢复是硬条件。** Claude Code CLI、Codex CLI、Codex Desktop 的原生续聊必须在声明支持的组合上实际演练通过；可读导出不能替代原生恢复（PRD §8、G0）。
3. **支持能力以实测为准。** 每个 Agent × 版本 × OS × 运行环境的组合都登记为 `supported / partial / unsupported`。尚未验证的组合标为“待验证”，不能写成已支持。
4. **不得默默缩减范围。** 开发中发现某项做不到时，要写入未解决项并由用户决定；不能靠实现细节改变范围（PRD Further Notes）。
5. **目标值要如实报告。** 非功能目标以实测报告；达不到时如实记录并说明优化方案，不用平均值掩盖 P95。
6. **只用合成数据。** 验收使用隔离账号、隔离的 Agent 配置目录和合成会话；不读取真实员工材料，不删除真实会话来模拟丢失。

| 合成样例 | 覆盖 PRD Testing Decisions 中列出的已知员工、项目、时间、工具结果、父子关系与预期证据位置 |

## 4. 非功能指标（AC-22）

| 指标 | 目标 | 测量方式 |
| --- | --- | --- |
| 安装耗时 | 已具备 Node / Agent 的环境，从开始安装到本地健康检查通过 ≤ 2 分钟 | 秒表 + 日志时间戳；下载、宿主信任、首次大历史同步分别记录 |
| hook 影响 | P95 ≤ 100 ms，含进程启动与本地写入，不等待远端网络 | 在登记环境中连续触发 ≥ 200 次，报告 P50 / P95 / 最大值 |
| 原文可见 | P95 ≤ 60 秒（受支持客户端、网络正常、约定试点负载；首次旧会话回填另计） | 事件时间与服务器可查询时间之差 |
| 日常负担 | 正常使用无需手动上传、额外提示词或日报填报 | 连续 5 个工作日的试点记录 |
| 可维护性 | 安装、升级、修复、整体卸载、服务器恢复都有可重复的流程 | 按文档由第二人复现一次 |
| 用量 | 分析并发、作业时长、输入规模与预算有限额；未知用量不计为 0，超限状态可见 | 配置与运行状态截图 |

## 5. Web 界面验收

界面结构以已选原型为参照，内容以 PRD §7 为准：

- **团队概览**：采用覆盖矩阵结构（员工 × 日期的覆盖状态 + 所选日期的活动统计 + 检查器）。统计只包括 PRD 规定的确定性字段：会话、用户轮次、工具调用、涉及文件、可取得的 Token、事件活跃区间。
- **员工日 / 周工作、项目视图、会话详情、会话找回、接入与设备、分析更正与运行状态**：逐页对照 PRD §7 的“必须支持的行为”。
- **全站**：
  - 空状态区分无活动、待信任、设备离线、采集缺口、分析未完成。
  - 大输出按页展开，导出保留全文。
  - 界面在 320—1920 px 宽度下可用、无横向滚动；深色模式对比度达标。

## 6. 验收产出物

1. **支持矩阵**：Agent × 版本 × OS × 运行环境 × 能力（采集 / 可读导出 / 原生恢复），每格为 supported / partial / unsupported，并附重现实验。
2. **AC 对照表**：AC-01…AC-22 逐条列出步骤、实际结果、证据链接和未解决项。
3. **故障注入与恢复演练记录**：G2 的全部实验、服务器整套恢复演练。
4. **非功能实测报告**：环境、负载、样本数、P50 / P95 / 最大值、异常说明。
5. **安装页与已知限制**：npm 与插件市场两条入口的真实步骤。

## 7. 不在 V1 验收范围

以下内容由 2026-09-24 的原型提出，属于 V2 候选，**不作为 V1 通过条件**，V1 也不要求实现：

- 数据报表：用量与产出、会话产效比、提示词分析、响应与等待。
- 活动记录（按时间节点的对话事件流）与会话对话视图。
- 会话组装与去重的可视化页面。注意：**去重与组装本身的正确性属于 V1**，即 AC-07、AC-08。

PRD 原有的范围外事项仍然不做：外部 Git / PR / CI 关联、自动评分或排名、精确工时、批量导入未继续的旧会话等。

## 8. 签收

V1 完成需要产品负责人确认第 6 节全部产出物，并在 Issue #1 记录验收结论与未解决项。
