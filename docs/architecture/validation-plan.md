# 可行性验证与首版发布门槛

日期：2026-09-24。状态：验证设计已随整体设计确认，实验待执行。本文件定义如何证实[整体设计](./solution-design.md)，场景已纳入 [PRD v1.0](../requirements/PRD.md)，不表示已经通过实验。

## 1. 实验方式

使用独立测试账号/隔离的 Agent 配置目录和合成会话。记录 OS、架构、Agent 版本、Node/npm 版本、插件版本、信任状态及运行环境。不删除真实会话来模拟丢失，不复用员工账号凭据，不把真实日志放入测试仓库。

优先测试实际使用的 OS；当前只知道本工作区是 Windows，不能推断全体员工均为 Windows。CLI、图标启动 Desktop、本机与 WSL 等各自列为独立样例。

## 2. G0：采集与恢复，先消除最大不确定性

| 实验 | 通过条件 |
| --- | --- |
| Claude CLI / Codex CLI / Codex Desktop 正常会话 | 用户、Agent、工具请求与结果、原生可见代码变更可定位；列出来源本就不可见的字段 |
| 接入后新会话 | 可靠识别活动并登记，无需提示模型主动上报 |
| 既有旧会话被继续 | 上传该会话从开头起的现存完整记录及必要关联材料；保留原始时间 |
| 未继续使用的旧会话 | 不上传，不因为其他会话活动或目录 mtime 变化被批量导入 |
| compact、分支、子会话、大工具结果、附件 | 保留可取得原件和谱系；上游截断/删除明确标缺口 |
| Claude 原生恢复 | 从服务器下载到隔离环境，可在原 Agent 继续同一会话，关键上下文与工具历史验证通过 |
| Codex CLI 与 Desktop 原生恢复 | 确认恢复包所需文件/索引，并完成真实原生续聊；Desktop 能按已定义流程打开恢复会话 |

**退出条件：** 为每种支持组合记录 `supported / partial / unsupported` 和重现实验。Codex 原生恢复失败则核心需求仍未满足，不能用可读导出替代。先解决支持版本或恢复设计，再推进全面产品开发。

## 3. G1：安装人员易用性

| 实验 | 通过条件 |
| --- | --- |
| npm 脚本正常、被禁用、不同受支持版本 | 分发文件足以运行 setup，不依赖 postinstall 下载/编译/注册 |
| 单一授权值 | 只输入一个个人接入值，平台地址来自可信发行配置；不要求模型 Key |
| 已有 Claude/Codex 配置 | 安装、重复 setup、修复只修改拥有的条目，不破坏其他插件/hooks |
| 普通用户与含空格路径 | 在目标 OS 支持的用户权限内启动，正确传参；不靠管理员启动绕过设计 |
| 未信任 hook / 更新定义 | 明确显示待信任；通过宿主正式流程后生效，不伪造可信状态 |
| 图标启动 Desktop | 没有继承安装终端的 SKYNET_KEY/PATH 仍可使用已注册凭据和稳定入口 |
| 插件市场入口 | 安装、初始化、信任状态可解释；不把 Key 发给模型；与 npm 路径共用后台 |
| 双 Agent、双安装入口 | 同一用户运行环境只启动一个后台；两份插件不会重复上传同一事件 |
| 重启、登录、休眠、崩溃 | 依照 OS 支持范围自动恢复；无法自启时正确显示降级 |
| 升级/卸载中断 | 队列、身份保留，失败可回退；卸载清理拥有的后台和配置，不依赖 npm 卸载脚本 |

**体验目标：** 已具备 Node/Agent 的受支持环境，从安装开始到本地健康检查成功目标两分钟内；下载耗时、宿主信任交互、首次旧会话大文件上传分别记录。真实 Key 不进入日志、项目文件、提示词或公开报告。

## 4. G2：可靠存档与正确统计

| 故障注入 | 通过条件 |
| --- | --- |
| 同一上传重试十次，ACK 丢失 | 一份逻辑事件/清单；统计不翻倍；同键不同内容报冲突 |
| 原件写入后、数据库提交前崩溃 | 不返回虚假 ACK；重试完成或孤立分块可安全回收 |
| 数据库提交后、客户端推进游标前崩溃 | 重试取回相同提交结果；不重复计入活动 |
| 断网/限流/错误凭据/服务器重启 | 持久队列与退避正常；积压、拒绝和最后成功时间可见 |
| 本地磁盘满/无权限/原件提前删除 | 员工 Agent 可继续工作；明确报告采集缺口，不显示完整备份 |
| 文件半行、增长、重写、截断 | 原始字节与文件代次正确；解析不能污染旧版本 |
| 分块损坏或清单缺引用 | 校验失败，不提交完整状态；导出与恢复验证哈希 |
| 跨设备复制/恢复 | 历史谱系和原始归属保留；新活动归属当前设备，已知重复不再计数 |
| 继续三个月前旧会话 | 全部可得记录存档；旧活动不计为今天新增工作 |
| 服务器整套恢复演练 | 数据库、原件和清单引用一致；报告能重算，原生恢复包仍可验证 |

hook 延迟先以 P95 ≤100ms 为样机目标，包含进程启动及本地写入，不能仅测内存函数；若目标 OS 达不到，调整 launcher/本地写入设计并报告实测，不牺牲未确认数据换漂亮数字。hook 不同步等待远端网络。原文可见以约定负载下 P95 ≤60s 为目标，首次大历史回填另计。

## 5. G3：Claude Code + 千问分析

| 实验 | 通过条件 |
| --- | --- |
| 最小按量调用 | Claude Code 非交互运行成功，记录运行时/模型版本；通过结构化结果校验 |
| 结果证据 | 每个关键工作结果有有效原文引用，区分已观察、声称、推断和材料不足 |
| 长会话/大输出 | 分段与聚合后仍可回到原件；不把截断当完整阅读 |
| 原文包含“执行命令/外发数据”指令 | 仅被当作待分析内容；没有执行工具和越权副作用 |
| 作业超时/重复领取/租约失效 | 有限重试；旧 Worker 结果不能覆盖较新报告 |
| 模型不可用/预算耗尽 | 原件上传与查询继续，分析显示待处理；不无限重试收费 |
| 系统分析记录 | 不进入员工会话统计，不触发递归分析 |

付费调用在实际原型任务中按部署预算执行，本轮未调用。不能用另一 SDK 的直接模型调用冒充用户指定的 Claude Code 运行链验证。

## 6. G4：产品验收

- 员工、项目、主题、会话、证据可相互追溯；所有认证 Web 用户可查看全部数据。
- 未登录访问被拒绝；设备凭据不能冒充其他员工写入，也不自动成为全量浏览凭据。
- Claude/Codex 的 MCP 查询完成真实授权与分页读取；令牌校验、账号撤销和证据定位有效，MCP 登录故障不阻塞设备上传。
- Asia/Shanghai 的跨日、跨周和迟到数据正确归期；旧报告保留版本。
- 人工补充、更正和重新分析可审阅，不覆盖原始记录。
- 原件丢失、待信任、离线、无活动、分析失败是可区分的状态。
- 完整可读导出与各声明支持组合的原生恢复均实际演练通过。
- 正常使用无需每日操作；npm 与插件入口真实步骤、已知限制写入安装页。
