# 以完整会话材料作为存档目标

用户在第一轮访谈中选择保存完整工作对话、命令、工具结果和代码变更，并新增本地会话丢失后从服务器导出找回的需求。因此平台以完整会话材料为存档目标，摘要和统计不能替代原始材料。只保留摘要虽然存储与处理成本较低，但事后无法重建已经丢失的过程细节，也不足以支持用户要求的找回能力。

这项选择意味着需要承担原始内容的存储、访问管理和备份成本。第二轮已经明确：所有项目的会话均采集，既支持完整记录导出，也以原生续聊为恢复目标；未选择工作文件与环境恢复。第三轮接受原件默认不自动删除，并在后续补充中去掉接入前的历史批量导入；接入后断网产生的积压仍属于正常同步。

用户进一步明确：接入后继续使用旧会话时，同步该会话完整记录，以保留恢复需要的上下文；其余旧会话不扫描导入。源头可提供的内容、完整性与恢复兼容性仍须验证，不能将已采到的部分材料称为完整备份。
