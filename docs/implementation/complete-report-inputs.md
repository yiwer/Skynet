# 完整内部报表输入与响应预算分离

容量诊断使用公开上传准备的 10 人、4 周、1,000 会话、80,000 条业务事件、19,000 段等待与 20 份适用分析。来源 fixture、数据规模与性能目标未修改。这一片只处理内部组合报表错误继承传输预算的问题，不表示 AC-32 性能或全部容量验收通过。

`usage.complete(selection, { full })` 与 `waits.complete(selection, { full })` 返回完整不可变版本；指定 `version` 时仍检查原来的范围、员工、来源、项目和指定周。内部完整输入不接受分页或对话行选择，`full` 不接受旧版本。当前读取仍校验实际原件；完整性、归属、未知值、版本内容及重试规则没有改变。每次全量重算与当前读取经过同一个物化路径。

公共 HTTP/MCP 继续调用原有 `read`；公共重算仍在完成物化后应用原来的首页预算。下载保留原预算。等待的 20,000 原件、128 MiB 原始输入、最长日期范围及 Usage 的原件数量和完整存储限制均保留。没有新增跨请求原件缓存。

组合报表使用完整输入，避免为取得一个版本先构造 Usage 首页或 waits 下载。固定输入关联与外层来源一致性检查继续由原来的组合服务负责。

本片未处理 Usage 大范围首页中的嵌套集合分页、会话产效大结果存储、等待与产效完整下载。这些现存限制不应被写成通过，也没有通过删上限或缩小查询范围回避。

公开回归位于 `tests/complete-inputs-capacity.test.ts`。可设置 `SKYNET_CAPACITY_SOURCE` 指向经过完整清单与哈希核验、停止后的 AC-32 合成源态，测试只复制并修改自己的数据库和原件；未设置时通过同一公开 fixture 建立完整规模。源态中的合成凭据不得写入公开证据。各阶段 RED/GREEN、最终回归和独立验收在仓库外 `54-complete-inputs-*` 证据中记录，耗时仅为功能验证耗时，不作为 P95。

作者全规模公开回归已通过（217.56 秒，共享宿主的功能验证）：原 413 的等待统计、提示词全量重算和个人评估分别保留 RED，再转 GREEN。最终用同一个自有 clone 验证 19,000 段等待、20,000 条提示词（400 条有适用分析、19,600 条未知）、100 个本人会话，以及三种报告的固定 HTTP/OAuth MCP 一致性。MCP 客户端结果序列化分别为 14,201 / 18,989 / 15,071 字节，这些是本次返回值大小，不是全站容量声明。

补传一条真实原生用户记录后，等待和提示词总量分别为 19,001 / 20,001，本人提示词为 2,001；当前结果与全量重算相同，重启后旧报告和完整 Usage 导出保持原样。固定版本套用错误员工、来源或项目均被拒绝，尾页等待引用完整。该测试不把尚未修复的公共大响应 413 当作通过。
