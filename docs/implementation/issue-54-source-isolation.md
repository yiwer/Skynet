# #54 原件故障隔离

本切片修复已成功上传的原件在存储中丢失或哈希不符时，当前洞察、等待、活动及画像组合读取互相牵连的问题。它不代表 #54 的性能与全部上线验收已经完成。

## 行为与边界

- `RawUnavailableError` 只表示明确的文件缺失、不可读取与哈希不符。数据库异常、归属变化、资源上限等错误仍按原错误路径返回，不转换为正常未知数据。
- 当前洞察批量准备逐件重新读取并校验原件。失败对象返回 `sourceAvailability`、未知事实与不可用推断；不写入正常事实投影。全局旧来源修复仍处理可用来源，仅跳过实际不可读取的对象，不缩小既有跨快照证明范围。
- 等待输入保留失败来源及已登记归属，不捏造消息、日期、区间或零时长。`unavailableSources` 与未知原因随固定等待版本保存；已确认区间仍可读。同一逻辑会话的坏副本不算另一段并行活动；其他逻辑会话来源不可读时，其并行状态保留未知。
- 活动列表用无来源时间的缺口呈现不可读来源；会话产效使用未知起止与时长的缺口段。找回副本仍归原员工，坏来源不污染无关员工的等待、用量或画像。用量仍保留团队行及所选标记。
- 当前活动和产效准备同时核对洞察与等待输入的可用性、原件哈希及归属版本，不保存不同观察混合的结果。等待算法版本为 `recorded-waits-3`，活动算法版本为 `activity-2`；旧固定版本保持可读。
- 原件详情、下载和材料渲染保留派生缓存，但每次当前读取先重新读字节并校验 SHA；缓存不能掩盖物理故障。HTTP 返回不含文件路径的 503 `source_unavailable`，MCP 与 Web 明确显示“原件不可读取”。材料丢失不阻止独立可读的主原件下载；包含该材料的完整导出会报告不可读。
- 字节恢复后，当前读取重新使用正常事实；故障期间冻结的未知视图与故障前固定报告均不改写。没有跨请求的可用性 TTL。

## 公开验证

所有新用例通过真实上传、HTTP 查询、OAuth MCP 与浏览器入口验证，只破坏各自隔离沙箱中的合成原件，并在 `finally` 恢复。未读取员工实际内容、调用付费模型或写入生产环境。

测试文件：`tests/source-isolation.test.ts`、`tests/source-isolation-journey.test.ts`。覆盖暖读取的丢失与哈希不符、冷读取后恢复、正常员工团队参照、固定历史、全量等待重算、跨员工找回、同会话与不同会话并行、材料下载、完整导出、直接打开和下载失败提示，以及 HTTP/MCP/导出一致性。

外部证据：`E:/GenCode/Skynet-evidence/v2-2026-10-04/54-source-isolation/`。逐片 RED 分别复现洞察 500、等待 500、同会话坏副本被判并行未知、Web 尚未分析、等待错误空态、暖详情返回旧正文、MCP 泛化错误；GREEN 与最终集成结果见 `manifest.json`。既有原件完整性、材料恢复、用量、等待边界、活动和产效公开回归 22/22 通过，日志 `13-public-regressions.txt`。最终作者验证与独立合并结果另行记录，不能将共享主机上这轮功能测试计作性能达标证据。

后续等待批量准备需保留每次当前请求的字节复核、完整归属/证明修复、失败对象独立状态与跨项目/Agent 并行范围。读取事实可以批量准备，缺失原件不能作为空的正常事实缓存。
