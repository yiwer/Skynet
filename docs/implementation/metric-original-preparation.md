# 首次指标读取的原件准备

#54 的公开千会话探测在 `572cc4f` 首次读取仍为 7.228 秒，未达到 AC-32。后续读取复用已经单独接受；本改动只处理首次读取中重复解码和 JSON 解析的开销。

首次请求 CPU 探测保存在外部证据 `54-metrics-cold-key-profile.json` 与 `54-cold-key-cpu-summary.json`。原件事实准备累计 CPU 约 3.24 秒，主要来自同一原件的业务证据、原生用量和完整性覆盖分别解码、解析。该探测含 profiler，不能将单次时间当 P95。

`metricInputBatch` 对新鲜读取且已经校验 hash 的原件，在当前输入的调用栈中共享一次严格 UTF-8 解码和 JSON 解析。三种读取仍执行原有格式、来源版本、计数基线、辅助记录和消息完整性校验。没有跨请求原件缓存，没有将原生辅助记录变成业务事件，没有改变指标、证据或解析版本。

大于 1 MiB 的原件沿用原有读取方式，控制额外 JSON 对象的峰值；带起始 BOM 的原件也沿用原路径，保留各读取器既有 BOM 语义。无效 UTF-8 仍然拒绝用量推导；未完成尾行、无效 JSON、未知记录和不支持的消息保持原有缺口语义。Codex 业务解析器提前排除不属于其支持类型的行，仍计入 unrecognized，由覆盖读取器单独确认辅助记录。

验证沿用已经确认的公开上传 → HTTP / 导出边界，包括已知计数、来源日期、原件归属、机器上下文、未知与真实零、固定版本、全量重算、损坏 UTF-8 与旧材料。性能阈值沿用 3 秒 / 1 秒，不因此改动降低。

当前状态：作者构建通过，公开回归与性能复测进行中，尚未独立验收。#54、AC-32 保持未完成。
