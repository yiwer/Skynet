# 画像工作内容的固定读取快照

在一次画像读取中，已入队的日报或周报即使没有新增原件，公开刷新仍会递增 `generation`。此前画像把这些派生调度字段和所有日报、周报修订加入来源守卫；三次同源刷新即可耗尽三次尝试，返回 409。不能只删除这些字段：原来的工作内容读取逐次使用连接池，日期枚举、日报、周报及后页可能观察到不同的准备状态。

现在 `workContent` 使用一个 `REPEATABLE READ READ ONLY` 事务。日报和周报服务的内部 `readAt(reader, ...)` 使员工校验、日期枚举、版本选择、待刷新状态、来源修订检查和所有分页都使用同一连接；后页仍固定首屏修订。原有公开 `read` 的参数、分页预算和默认数据库读取行为不变。画像保存该快照中的工作条目和版本引用；下一次 live 读取可以得到新的准备状态，并形成不同的画像版本。

外层来源守卫保留原件、资格证明、分析、推断更正、投递记录和设备资料。人工日报更正的不可变 `(id, sequence)` 集合另按 `date, sequence, id` 排序纳入守卫，不能用单个最大序号代替各日期的完整集合。日报、周报的派生修订、代数和待刷新标志不再要求贯穿所有组合计算都不变化。算法标识为 `capability-profile-3`；旧固定画像仍直接读取原有不可变 payload。没有改变三次守卫、HTTP 状态、分页／计算上限、归属、未知值或原件验证规则。
