# #43 响应与等待报表

本票承接 #37 的不可变等待区间，覆盖 PRD-v2 US 126–130、AC-23/24/29/31。所有上传材料、员工、项目与 OAuth 客户端均为测试创建的合成对象，没有读取员工原件或写入生产。

## 统计来源与范围

`waitReportService` 只从 `waitsService.export` 取得完整固定版本，不从分页第一页计算分位数，也不重新解析轮次或推断用户是否在工作。`wait-report-1` 保存等待来源版本、范围、截至时间、算法和完整统计结果；`wait_report_revisions` 只追加。迟到的并行活动改变当前等待输入，旧报表仍使用旧区间和证据。固定报表版本与筛选不匹配时拒绝读取。

HTTP `GET /api/wait-report`、`GET /api/wait-report/export` 和 OAuth MCP `read_wait_report` 使用同一服务。支持本周、上周、接入至今、员工、Agent、项目；`version` 固定报表，`waitVersion` 可把统计绑定到已读取的等待记录。所有读取必须使用个人读取身份，设备凭据不能读取。报表响应有 80 KiB 上限，超过时明确要求缩小员工范围，不静默截断。

- 等待中位数取排序后的中间值，偶数样本取两个中间值均值；P90 使用离散 nearest-rank，即第 `ceil(0.9 × n)` 项。四分位采用线性插值，箱线分布保留最短、Q1、中位数、Q3、最长及 P90。
- 长等待比例是时长至少 600 秒的完整区间数 ÷ 已知时长区间数；并行比例是观察到其他会话活动的区间数 ÷ 并行状态已知的区间数。两项保留分子、分母；零样本结果为 `null`，未知区间不补零。
- 星期 × 小时热力图按等待起点的北京时间归组，周一至周日、00–23 时共 168 格。跨午夜的完整等待只落一格；范围内按日时长仍由 #37 的按日表提供，不将两者混为同一个统计。没有样本的格子显示无记录。
- 人员分布固定按姓名排列，以员工 ID 稳定处理同名；会话等待仍分别保留，不合并为员工工时。
- 当前支持的原生归档没有可信、成对的权限请求与批准/拒绝来源（依据见 #37）。权限中位数为未知，请求和允许列表建议为空；不使用工具执行时间猜批准时间，也不生成没有证据的建议。将来来源契约增加真实权限区间时，须发布新的统计版本，而非改写既有报表。

## 页面与可访问性

沿用 `#waits` 页面，五项 KPI、热力图、按人分布、权限来源和既有等待记录共用筛选与等待版本。每张图可以切换为等价表格，热力格与人员分布在键盘聚焦、鼠标经过时呈现相同信息。热力图与表格独立滚动；根文档固定。折叠的统计口径记录分位数、未知和非考勤含义，页面没有试验数据、排行榜或自动权限变更。

“导出统计”下载界面当前固定报表；原“导出当前版本”保留完整等待明细。重算沿用 #37 的原件重算，再以该等待版本生成统计。对话中的等待标记与证据入口保持兼容。
