# 组合报告的来源一致性准备

#54 的画像诊断在固定提交 `3b2a661` 上，3 人、36 会话、2,880 用户轮次仍需首次 8.219 秒，后三次 6.907 / 5.705 / 5.591 秒。已知数值、当前/固定版本和全量重算相等，最后因 1 秒阈值失败。证据 `54-frontier-profile-before.json`，不作为千会话 AC-32 结果。

组合报告每次前后校验来源身份时，只需要识别输入有没有变化，不消费逐快照的归属修订值。现改为调用已经独立接受的 `currentMetricInputs`，一次读取完整快照元数据、员工/设备归属与接入时间，并读取资格、完整性、修复、主原件覆盖四类追加证明的数量及最高修订。两者同时比较，覆盖序列号乱序提交；不只比较会话数或最新序号。原件 hash、manifest、provenance、提交时间均保留。

分析任务、适用分析目标、覆盖记录、人工更正，以及画像的投递、设备显示、日报/周报版本与 pending 状态仍按原样读取；事务隔离、前后比较、有界重试、保存时机和 20,000 原件上限不变。此身份只用于数据库来源变化判断，不证明原件可读取；各当前读取仍执行新鲜原件校验。

身份代次更新为 `reporting-frontier-2`，当前结果允许产生新版本，旧固定结果继续直接读取，不回写。验证使用公开交错上传/同原件集完成分析、固定历史、全量重算、投递变化与更正旅程。当前作者验证中，尚未独立接受，#54 保持开放。
